# bahriya_project_quota (Data Source)

Reads a project's resource allowance and how much of it is in use.

Every deployment is checked against this allowance before it is created. A container, Memcached or Valkey instance that would take a region past its ceiling is refused, and nothing is created or billed. Reading the allowance first lets you size a configuration that will be accepted, instead of finding the limit when an apply is refused.

The allowance is read-only. To raise it, raise a support ticket.

## Per region, not per project

The allowance **applies in full in every region a project runs in**; it is not divided between them. A deployment in three regions has to fit inside it three separate times. A project can be full in one region and nearly empty in another, so every figure here is reported per region and there is no project-wide total.

## Reservations and ceilings

Each region reports two pairs of figures, and each limit is enforced on its own:

- **reserved**: what the workloads are guaranteed.
- **ceiling**: the most they may use.

A ceiling is set above its reservation, so the ceiling is normally what runs out first. A project with plenty of reservation left can still be unable to accept anything.

`used` is what is reserved now. `peak` is what the same resources would reserve if every autoscaled workload grew to its maximum at the same time, which is the figure that decides whether they can.

## Example Usage

```terraform
resource "bahriya_project" "app" {
  handle  = "app"
  name    = "App"
  regions = ["falkenstein-1"]
}

data "bahriya_project_quota" "app" {
  project = bahriya_project.app.id
}

output "falkenstein_cpu_headroom" {
  value = one([
    for r in data.bahriya_project_quota.app.regions : r.available.cpu_ceiling
    if r.region == "falkenstein-1"
  ])
}
```

Sizing a container from the allowance instead of a fixed guess:

```terraform
resource "bahriya_project" "app" {
  handle  = "app"
  name    = "App"
  regions = ["falkenstein-1"]
}

data "bahriya_project_quota" "app" {
  project = bahriya_project.app.id
}

locals {
  # Every region carries the same ceiling, so the first entry is representative.
  ceiling = data.bahriya_project_quota.app.regions[0].available.cpu_ceiling
}

output "project_cpu_ceiling" {
  value = local.ceiling
}
```

## When a deployment is refused

If a resource would take a region past its ceiling, the apply fails with an error that names the region, the limit and the shortfall:

```
Error: Project resource limits exceeded

  with bahriya_container.api,
  on main.tf line 12, in resource "bahriya_container" "api":
  12: resource "bahriya_container" "api" {

This change needs 6600m of CPU ceiling in region falkenstein-1, but project "my-project"
has only 6500m free of its 8000m ceiling. Raise a support ticket to request an increase.
  falkenstein-1 / CPU ceiling: needs 6600m, 6500m free of 8000m
```

Nothing is created when this happens, so you can change the configuration and apply again without cleaning anything up.

A deployment that fits but cannot reach its `scaling.max_replicas` produces a **warning** instead of an error. It is created and runs, and autoscaling stops short of the maximum. The warning gives the number of replicas it can reach in each region.

# bahriya_tls_bundle (Data Source)

Reads a TLS bundle from the organisation's vault by handle, including its CA certificate and certificate. The private key is never returned.

Its main use is the certificate Bahriya manages for a `bahriya_mysql` or `bahriya_valkey` instance that has TLS on and no `security.tls_bundle` of your own. That bundle's handle is the instance's handle followed by `-tls`. Clients that verify the server (MySQL with `ssl-mode=VERIFY_IDENTITY`, Valkey with `--cacert`) need its `ca`. Renewals keep the same CA, so a saved copy keeps working. Replacing the CA, which you request in the console or with `reis mysql:replace-ca`, changes `ca` on the next refresh.

## Example Usage

```terraform
resource "bahriya_project" "shop" {
  handle  = "shop"
  name    = "Shop"
  regions = ["helsinki-1"]
}

resource "bahriya_mysql" "orders" {
  name      = "Orders DB"
  handle    = "orders-db"
  tier      = "single"
  cpu       = 500
  memory    = 1024
  project   = bahriya_project.shop.id
  regions   = ["helsinki-1"]
  databases = [{ name = "orders", username = "orders-app" }]

  persistence = {
    storage = 10
  }

  security = {
    tls = true
  }
}

data "bahriya_tls_bundle" "orders" {
  handle = bahriya_mysql.orders.security.tls_bundle
}

# The CA certificate clients use to verify the server, for example:
# terraform output -raw orders_ca > orders-db-ca.pem
output "orders_ca" {
  value = data.bahriya_tls_bundle.orders.ca
}
```

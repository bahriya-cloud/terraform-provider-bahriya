# bahriya_project_network_policy_attachment (Resource)

Attaches a network policy to a project, so it applies to every container and datastore in the project. The policy itself belongs to the organisation and is managed with `bahriya_network_policy`; one policy can be attached to many projects.

To apply a policy to one workload instead of the whole project, do not attach it here: list it in that workload's network policies instead (`networking.network_policies` on a container, MySQL or Valkey instance, `network_policies` on a Memcached instance). A policy applies to a project either as a whole or per workload, not both: attaching it to the project replaces any per-workload use of it in that project.

Changing `project_id` or `handle` replaces the attachment. Removing the attachment detaches the policy from the project and never deletes the policy.

## Example Usage

```terraform
resource "bahriya_project" "web" {
  handle  = "web"
  name    = "Web"
  regions = ["falkenstein-1"]
}

resource "bahriya_network_policy" "web_tier" {
  handle        = "web-tier"
  name          = "Web tier"
  ingress_peers = ["api"]
}

resource "bahriya_project_network_policy_attachment" "web_web_tier" {
  project_id = bahriya_project.web.id
  handle     = bahriya_network_policy.web_tier.handle
}
```

## Schema

### Required

- `handle` (String) Handle of the network policy to attach.
- `project_id` (String) ID (UUID) of the project the network policy is attached to.

### Read-Only

- `id` (String) Identifier of the attachment, in the form {project_id}:{handle}.
- `join_id` (String) Identifier the API gives this attachment. Empty after an import: the API does not return it for an existing attachment.

## Import

Import an attachment by the project's UUID and the policy's handle, separated by a colon:

```shell
terraform import bahriya_project_network_policy_attachment.web_web_tier \
  8a3d0000-1111-2222-3333-444444444444:web-tier
```

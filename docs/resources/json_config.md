# bahriya_json_config (Resource)

A JSON config: a versioned JSON document that any container in a project it is attached to can mount as a file. The content is checked as JSON on every create and update. Changing `content` creates a new version and makes it current.

A container mounts its JSON configs in `configs.json_configs`.

## Example Usage

```terraform
resource "bahriya_json_config" "app" {
  handle = "app-json"
  name   = "App JSON"
  content = jsonencode({
    server = {
      port    = 8080
      timeout = "30s"
    }
    features = {
      beta = false
    }
  })
}
```

## Schema

### Required

- `content` (String) Valid JSON content.
- `handle` (String) DNS-1123 compliant: lowercase alphanumeric and hyphens only.
- `name` (String) Display name of the JSON config, at most 100 characters.

### Read-Only

- `billable` (Boolean) Whether the JSON config is billed to the organisation.
- `created` (Attributes) When the JSON config was created (UTC). (see [below for nested schema](#nestedatt--created))
- `currentversion` (Number) Number of the version in use.
- `id` (String) Unique identifier (UUID) of the JSON config, assigned by the platform.
- `managed_by` (String) Identifier (UUID) of the platform resource that manages this JSON config, such as a MySQL instance. Null when the organisation manages it.
- `managedbyresourcetype` (String) Type of the platform resource that manages this JSON config, such as mysql. Null when the organisation manages it. A managed JSON config can be changed only by that resource.
- `max_versions` (Number) Number of versions kept. When there are more, the oldest are deleted; the version in use is never deleted. It is 5 by default and cannot be set through this API.
- `organisation` (String) Identifier (UUID) of the organisation that owns the JSON config.
- `rotated_at` (Attributes) When the version in use was written (UTC). Null until the JSON config has been rotated at least once. After a rollback, the date of the version rolled back to. (see [below for nested schema](#nestedatt--rotated_at))
- `updated` (Attributes) When the JSON config was last changed (UTC). (see [below for nested schema](#nestedatt--updated))
- `version_count` (Number) Number of stored versions, including the version in use.

## Import

Import a JSON config by its UUID:

```shell
terraform import bahriya_json_config.app 065df92e-4e46-436a-a0a0-aaaaaaaaaaaa
```

~> **Note:** The API never returns a config's content. After importing, set `content` in your configuration; the next apply writes it as a new version.

# bahriya_project_gpg_keypair_attachment (Resource)

Attaches a GPG keypair to a project, so the project's containers can use it. The keypair itself belongs to the organisation and is managed with `bahriya_gpg_keypair`; one keypair can be attached to many projects.

Changing `project_id` or `handle` replaces the attachment. Removing the attachment detaches the keypair from the project and never deletes the keypair.

## Example Usage

```terraform
variable "signing_public_key" {
  type = string
}

variable "signing_private_key" {
  type      = string
  sensitive = true
}

resource "bahriya_project" "web" {
  handle  = "web"
  name    = "Web"
  regions = ["falkenstein-1"]
}

resource "bahriya_gpg_keypair" "signing_key" {
  handle      = "signing-key"
  name        = "Signing key"
  public_key  = var.signing_public_key
  private_key = var.signing_private_key
}

resource "bahriya_project_gpg_keypair_attachment" "web_gpg_keypair" {
  project_id = bahriya_project.web.id
  handle     = bahriya_gpg_keypair.signing_key.handle
}
```

## Schema

### Required

- `handle` (String) Handle of the GPG keypair to attach.
- `project_id` (String) ID (UUID) of the project the GPG keypair is attached to.

### Read-Only

- `id` (String) Identifier of the attachment, in the form {project_id}:{handle}.
- `join_id` (String) Identifier the API gives this attachment. Empty after an import: the API does not return it for an existing attachment.

## Import

Import an attachment by the project's UUID and the keypair's handle, separated by a colon:

```shell
terraform import bahriya_project_gpg_keypair_attachment.web_gpg_keypair \
  8a3d0000-1111-2222-3333-444444444444:signing-key
```

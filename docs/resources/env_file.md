# bahriya_env_file (Resource)

An env file: a versioned set of environment variables that any container in a project it is attached to can use. The content is one `KEY=VALUE` pair per line; lines starting with `#` and blank lines are ignored. Changing `content` creates a new version and makes it current.

A container names its env files in `configs.env_files`.

## Example Usage

```terraform
resource "bahriya_env_file" "api" {
  handle  = "api-env"
  name    = "API env"
  content = <<-EOT
    # API runtime configuration
    LOG_LEVEL=info
    METRICS_ENABLED=true
    REGION=eu-west
  EOT
}
```

## Schema

### Required

- `content` (String, Sensitive) KEY=VALUE pairs, one per line. Comment lines (#) and blank lines are allowed.
- `handle` (String) DNS-1123 compliant: lowercase alphanumeric and hyphens only.
- `name` (String) Display name of the env file, at most 100 characters.

### Read-Only

- `billable` (Boolean) Whether the env file is billed to the organisation.
- `created` (String) When the env file was created (UTC).
- `current_version` (Number) Number of the version in use.
- `entries` (Number) Number of KEY=VALUE entries in the version in use, not counting comment and blank lines.
- `id` (String) Unique identifier (UUID) of the env file, assigned by the platform.
- `managed_by` (String) Identifier (UUID) of the platform resource that manages this env file, such as a MySQL instance. Null when the organisation manages it.
- `managed_by_type` (String) Type of the platform resource that manages this env file, such as mysql. Null when the organisation manages it. A managed env file can be changed only by that resource.
- `max_versions` (Number) Number of versions kept. When there are more, the oldest are deleted; the version in use is never deleted. It is 5 by default and cannot be set through this API.
- `organisation` (String) Identifier (UUID) of the organisation that owns the env file.
- `rotated_at` (String) When the version in use was written (UTC). Null until the env file has been rotated at least once. After a rollback, the date of the version rolled back to.
- `updated` (String) When the env file was last changed (UTC).
- `version_count` (Number) Number of stored versions, including the version in use.

## Import

Import an env file by its UUID:

```shell
terraform import bahriya_env_file.api 065df92e-4e46-436a-a0a0-aaaaaaaaaaaa
```

~> **Note:** The API never returns an env file's content. After importing, set `content` in your configuration; the next apply writes it as a new version.
